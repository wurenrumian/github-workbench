# 排查手册

常见问题的原因和最快验证方式。改代码之前，先按这里确认是「环境问题」还是「GitHub 改版」。

## 装好后首页完全没变化

1. 确认当前地址是 `https://github.com/` 或 `/dashboard`。扩展只接管这两个路由，仓库页、issue 页一概不动。
2. 确认扩展是启用状态，并且**当前标签页已经刷新过**（`chrome://extensions` 里刚点完刷新，旧页面还跑着旧脚本）。
3. 打开 DevTools Console，看有没有 `[ghw]` 开头的报错。
4. 确认登录着 GitHub。未登录会被重定向到登录页，工作台没有数据可用。
5. 弹窗里的总开关是不是被关了。

## 某个面板一直是空的

先判断数据源还在不在：

- Issue / PR 面板走 `/search`，打开 `/search?q=is%3Aissue+assignee%3A%40me&type=issues`，看页面上有没有结果。
- 贡献日历打开 `/users/<你的登录名>/contributions`。
- 最近更新打开 `/<登录名>?tab=repositories&sort=updated`。

页面本身有内容、扩展里却是空的，通常是解析选择器过期了，见 [数据从哪来](./data-sources.md) 和 README 的「当 GitHub 又改版了」。

页面本身就是空的，说明入口变了（例如又变成纯 React 壳），换数据源，不是改解析器能解决的。

## 手动添加的仓库只有名字

元信息是异步补的：卡片会先显示「正在读取仓库信息…」，拉到数据后自动变成描述 + topics + 语言 + star / fork。

- 一直不更新：点顶部「刷新」。
- 还是不行：这个仓库可能被 GitHub 限流或页面结构变了，打开 `/<owner>/<repo>` 和 `/search?q=repo:owner/name&type=repositories` 各看一眼。
- 仓库元信息缓存 1 小时，想强制重拉就去弹窗点「清缓存」。

## 卡片拖不动

- 「关注的项目」的卡片：按住卡片后**移动鼠标**才开始拖；只按下不移动是点击。
- 面板排序：要按住面板**标题栏**再拖，正文区域故意不响应，避免影响选中文字。
- 只支持鼠标，触屏和键盘暂时不行。

## 颜色 / 主题不对

样式全部走 GitHub 自己的 CSS 变量（`--fgColor-*`、`--bgColor-*`）。如果某个主题下颜色奇怪，多半是该主题覆盖了这些变量；先在原生页面确认同样的颜色是否正常。

## 数据看起来是旧的

- 默认缓存 10 分钟，弹窗里可调。
- 顶部会显示「更新于 HH:MM · 缓存 N 分钟」，红色表示这次有数据源抓取失败、正在用旧缓存。
- 想立刻更新：点「刷新」；想连缓存一起清掉：弹窗里的「清缓存」。

## 装了两个同类扩展

两个都接管首页时会互相抢挂载点，表现为版面错位或来回闪。关掉其中一个，再刷新页面。

## GitHub Enterprise

`manifest.json` 里的 `matches` 只写了 `https://github.com/*`。自托管域名需要自己加一条，并且页面结构可能和 github.com 不一致。
